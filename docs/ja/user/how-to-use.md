# 利用者向けマニュアル

> 対象: 「利用者ロール」を持っている人。タスクを実際に消化する人向け。

## 1. 基本のながれ

1. プロジェクト用フォーラムでスレッド（＝タスク）を作る、もしくは既存スレッドを開く。
2. 着手したくなったら `/task transition state: in_progress` を実行（スレッド内で実行）。
3. 完了したら `/task transition state: done` を実行。
4. アクティブタスク一覧チャンネルから消える。完了タスクは履歴に残る。

## 2. 主要なコマンド

すべてフォーラム内のスレッドで実行してください。

| コマンド                                           | 意味                                           |
|----------------------------------------------------|------------------------------------------------|
| `/task transition state: not_started`              | 未着手に戻す                                  |
| `/task transition state: in_progress`              | 着手中にする                                  |
| `/task transition state: done`                     | 完了                                          |
| `/task transition state: cancelled`                | キャンセル（理由はスレッド本文に書きましょう）|
| `/task list`                                       | 自分が見るべきタスク一覧（ephemeral）          |
| `/task assign user: @誰か`                         | 担当者を指定（任意）                          |

## 3. 通知について

数日（管理者が設定した日数）状態が変わらないと、通知チャンネルで利用者ロール全員にメンションが飛びます。ロール全員に通知が行くので、放置しないようにしてください。

通知の間隔は `notify-cooldown`（管理者が設定）で決まります。デフォルトは 24 時間。

## 4. アクティブタスクチャンネル

サーバーには専用の「アクティブタスク」チャンネルがあります。

- Bot のみが書き込みます。書き込み禁止です。
- 「未着手」と「着手中」のタスクが一覧表示されます。
- 状態が変わると 1 分以内に表示が更新されます。

## 5. やりがちな勘違い

- **コマンドがエラーになる** → 「利用者ロール」がついていない可能性。管理者に依頼してください。
- **状態を変えたのに一覧に反映されない** → 30 秒〜1 分待ってください。それでも更新されないときは管理者に連絡してください。
- **完了タスクを後で見たい** → フォーラムのアーカイブ一覧から探してください。

## 6. 自動生成されるタスク

管理者が「監視カテゴリ」と「トリガーパターン」を設定している場合、特定の名前を持つチャンネルが作られたタイミングで自動的にタスクが立つことがあります。タスクが急に増えたように見えても慌てず、まずは内容を確認してから着手してください。
